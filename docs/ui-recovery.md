## Evidence and scope

The pre-repair tree was archived and hash-verified outside the project at:
`C:\Users\OR3OT\AppData\Local\Temp\opencode\RecurCIV-recovery-20261105-070640`.
It contains source, headers, tests, docs, build.py, payload, references, the previous

was used for this recovery. Existing unrelated work remains in the tree.

Confirmed causes:

* `view.c` retained the old renderer while `view.h`, `main.c` and
  `controller_route.c` retained the newer screens and actions. Home correctly
  entered `SCREEN_CONTROLLER_MENU`, but that enum had no renderer. A catch-all
  `else` painted USB Diagnostics for the Controller menu, Studio, Library,
  details and delete screens. Input still belonged to the real menu, so A selected
  Standard Controller despite the false "A Reset USB" label. This was **not**
  evidence of Home being routed to the Diagnostics enum or numeric enum collisions.
* The same old renderer contained cyan Home selection, old subtitles, bright
  keyboard fills, missing menu touch targets and inconsistent branding. The
  added `footer_frame()` was unused.
* `view_macro_step()` used overlapping snprintf source/destination buffers and
  corrupted labels. Earlier negative-pointer and unsigned-comparison warnings
  had been replaced with another invalid implementation, not a correct append.
* `run-tests.cmd` checked only `if errorlevel 1`. A fresh baseline run printed
  assertion failures in `test_text` and `test_macro_view` but continued because
  Windows assertion aborts return negative codes. Earlier runs of existing EXEs
  were not proof of a successful fresh build/test.
* No stale previous-cycle `Action` was found: main initializes it each iteration.
  Routing delegation is intentional and retained. The input boundary nevertheless
  allowed simultaneous touch to be interpreted on a screen just opened by a
  controller event; this is now gated by sampled screen and consumption state.

## Targeted recovery

Explicit renderers/touch targets are restored for every defined screen. Diagnostics
has an explicit branch; unknown screens cannot masquerade as Diagnostics. The
shared header and footer use the requested palette; footer rendering and hitboxes
share one specification. Home retains the CIV/Keyboard/Controller order, requested
subtitles, gold icons and gold focus. Studio options remain placeholders with
dismissible notices. Library browsing, metadata, pagination and deletion are
presented without changing RCMS or storage code.

Main still uses the existing controller route/mode and exclusive transport. It
does not reprocess an exit-cycle shortcut or deliver touch to a new destination
screen in the same sample. Menu selection navigation is a small shared production
helper so D-pad/stick tests exercise the same selection code as main. Diagnostics
A explicitly produces the existing USB-reset action, not Standard Controller.
Opening Controller/Studio/Library remains local.

Keyboard chips moved outside the footer, with file count beside the path.
Live Keyboard's new touchscreen Done invokes the existing nonblocking exit;
key layout, queue and 80/80 ms timing are unchanged. Controller history, held inputs,
axes, synchronization/disconnect statuses, Diagnostics, Exit and the forwarded
Plus+Minus shortcut remain visible. Ordinary exit remains neutral-completion gated.
