# RecurCIV v1.1.0

Live controller recording, persistent passthrough, Capture-button controls and
improved macro playback timing.

## What's new

- **Live Record:** record physical controller states while forwarding inputs to
  the connected USB host. Local-only recording remains a separate option.
- **Persistent passthrough:** enter Live Record to acquire the controller session;
  forwarding continues before, during and after recording, following the neutral
  synchronization/release safety gate.
- **Capture Start/Stop:** short-press Capture to toggle recording, or use the
  touchscreen controls. Capture is never forwarded or stored in macro steps.
  Unsupported registration shows touchscreen fallback. Short-press screenshot
  handling is reserved during live sessions and restored on exit.
- **Review and editing:** touch Exit live, wait for neutral cleanup, then review,
  edit, save, load and replay. Replacing unsaved captured states requires an
  explicit decision.
- **Playback timing:** full scaled holds start at successful state submission,
  instead of restarting after USB completion. This eliminates cumulative USB
  completion latency in tested fixed-latency scenarios while preserving every
  state, completion ordering, ownership and neutral cleanup. No catch-up skipping
  or artificial duration compression is used.
- **Recovery:** captured data survives disconnects, limits and cleanup failures;
  cleanup retries send neutral only and never automatically resume recording/playback.

In deterministic production-USB simulation, sixty 100 ms states with 5 ms
transfers improved from **6,600 ms to 6,000 ms** active playback; the 8-second
four-direction test improved from **8,420 ms to 8,000 ms**. These are host-test
results, not a guarantee of identical in-game movement.

Release verification includes the complete host suite (25 C suites and 6 Python
checks), the ARM NRO build, archive CRC/path/content validation, and rebuilding
the corresponding source ZIP to confirm it produces the same NRO.

## Downloads and installation

- **RecurCIV-v1.1.0.zip** — extract to the SD-card root. The application belongs at
  `sdmc:/switch/RecurCIV/RecurCIV.nro`. Keep the accompanying license notices.
- **[RecurCIV-v1.1.0-source.zip](https://github.com/OR3OTHUG/RecurCIV/releases/download/v1.1.0/RecurCIV-v1.1.0-source.zip)**
  — complete corresponding application source, assets, tests, build/packaging tools,
  editable payload source/generator, upstream/runtime source snapshots and notices,
  supplied alongside the binary at no additional charge.

Existing macro files and settings remain compatible. The installer does not
contain replacement user settings or macro files. Full application mode is
recommended; touchscreen access is needed for session exit/recovery and replacing
unsaved recordings.

## Known limitations

- Recorded controller inputs may not exactly match what the USB host received
  during live passthrough: latest-state forwarding can omit brief sampled states.
- Analog stick sampling, USB polling, rendering/application scheduling and game
  frames can introduce small movement differences. Slow transfers or delayed
  ticks can stretch playback; exact final positions are not guaranteed.
- Capture-button behavior can vary with the homebrew launch environment.
  Registration failure preserves touchscreen controls. Long-hold/video behavior
  and screenshot restoration need broader hardware testing.
- USB compatibility across different Switch hardware, docks, cables and USB-role
  setups is not fully verified. Native Switch 2 execution has not been tested.

USB descriptors/device identity, the approved Civ VII payload, keyboard behavior,
RCMS storage format and existing speed/repeat controls are preserved.

RecurCIV's combined distribution remains GPLv3 (`GPL-3.0-only`). Original Plume
USB, CivSwitch, exploit-source, runtime, library and font notices/attribution are
preserved in both archives. See `COPYING`, `LICENSING.md` and `CREDITS.md`.
